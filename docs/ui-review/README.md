# UI review evidence — 2026-09-05

Read [UI_REFACTOR_PLAN.md](../UI_REFACTOR_PLAN.md) for findings, source anchors,
acceptance criteria, priorities and review limits. This folder contains review
artifacts only; it is not part of the application or its automated test suite.

The 71 PNG screenshots were generated by real Chromium rendering of checkout
`364af6192a9dc8b8256d429ff777869189a35145`. No production screenshots or private
baseline metrics are included. JSON observations record route, viewport, visible
text and focused diagnostic results. The fixture corpus uses fictional names
and documentation IP addresses. Some specialized renderer fixtures deliberately
combine capability families; they do not claim real-device support.

## How to use the evidence

The plan's finding IDs link to the most useful images. Additional screenshot
names correspond to scenario names in these reports:

- `baseline.json`: setup and all main pages, role navigation, public asset parity.
- `populated.json`: Devices, Access, Compute, Settings, wizard and VPN fixtures.
- `diagnostics.json`: account lifetime, request race, polling and touch sizing.
- `specialized.json`: driver renderer families, NAC, controls and error states.
- `shell.json`: actual cached-offline boot, API docs and hash edge cases.
- `remaining.json`: dashboard CRUD, Logs, NAC settings and morning results.
- `performance.json`: one local login-shell resource/paint sample.
- `fixture-data.json`: reusable fictional input payloads.

Read screenshots at their original width. Long full-page screenshots of a modal
capture its current scroll position, not every internal section. Areas of the
underlying document may also appear below the viewport. That alone is not
evidence of a modal height defect. Scenario 43's filename mentions focus escape,
but its recorded Shift+Tab check **passed**; the confirmed shared-dialog issues
are missing semantics and premature scroll unlock, documented as M02.

Baseline `index.html` parity is false before normalization because HTTPS rewrites
the Apple touch icon URL. A separate comparison normalized only that attribute
and matched exactly. The JavaScript/styles/worker comparisons require no
normalization. This establishes deployed frontend parity only.

## Reproduction workflow

Use the isolated development command in the plan. Do not point browser fixtures
at the deployed service or reuse its data directory. Activate `.venv` before
Python commands. The review used Node 24.19.0, Playwright 1.61.1, Chromium from
`/srv/playwright-browsers/chromium-1228/chrome-linux64/chrome`, and Python 3.14.7.

The temporary review harnesses executed were:

```text
node /tmp/hlhq-ui-baseline.cjs
node /tmp/hlhq-ui-populated.cjs
node /tmp/hlhq-ui-diagnostics.cjs
node /tmp/hlhq-ui-specialized.cjs
node /tmp/hlhq-ui-shell.cjs
node /tmp/hlhq-ui-remaining.cjs
```

These are session-local review tools, not durable commands for future CI.
Promote the documented reproductions into `e2e/` before implementation. Existing
`e2e/support/fixtures.mjs` supplies `json`, `signIn` and roster helpers; this
folder's JSON supplies the broader data. Always mock integration reads/actions
and deny unexpected domain requests in a future maintained harness. Use a real
test-only login for session-isolation tests; keep cookies/storage-state files
outside the repository. The retained JSON contains no cookie or password values.

Key deterministic recipes:

1. H01: load fictional A devices under account A; logout; authenticate B; fail
   B's device GET with 503. Assert A's device is absent after the future fix.
2. H02: count initial detail GETs from a single Details click. Then hold all A
   detail responses, open B, let B render, release A. Assert heading, content,
   active request generation and any intercepted action all still refer to B.
3. H03: install the Playwright browser clock before boot; count Devices GETs
   after 16 seconds, leave for 16 seconds, return, then advance another 31
   seconds. Counts were 2, 3, 3. Idle Compute's read count stayed 2 across a
   subsequent 301-second advance. Yield to request completion between steps.
4. M01: with NAC unconfigured, render Zulu .20, Alpha .10, Guest .25; change the
   visible sort to IP. The original table preserves the unsorted order.
5. H05: return 503 from the manual Access refresh. Observe both page errors
   and rendered feedback. For offline boot, allow service workers, wait for
   registration, reload online, set the browser offline, reload again.
6. M04: create a 390×844 touch/coarse context and measure computed field sizes,
   not only CSS declarations. The original auth field is 12px despite the
   broad touch override. Physical iOS zoom behavior remains untested.

The roster timing harness entered Access after switching from Devices, awaited
the expected row count, and included a fixed 150ms settle delay. Input work was
timed synchronously around dispatching an input event. Those samples describe
this harness and should not become CI latency thresholds. The fresh login-shell
sample recorded 160ms load, 240ms first contentful paint, and 28 module responses
totaling 372,211 transferred bytes on loopback with no throttling. Measure again
under controlled repeated conditions before changing loading strategy.

## Verification and privacy

The full repository verifier ran twice and passed both times. Final result:
369 pytest tests, 67.94% coverage, 25 Playwright tests, six passing stages,
zero failures/skips. The final local log is
`/tmp/homelabhq-ui-final-verification.log`.

Only fictional local accounts and a temporary local dashboard were created.
The review dashboard was renamed and deleted; its empty configuration was
disposable. The local diagnostic ring was cleared during the Logs workflow;
the test server's stdout observations remain in the tool transcript. No
production dashboard, diagnostic log, credentials or external device changed.
Private pre-existing untracked measurement files were left untouched.

Screen readers, actual Safari/iOS/Android, browser zoom and real infrastructure
execution were not verified. `/docs` was blank at its two-second capture while
ReDoc rendered; Swagger asset initialization needs a separate network trace.
These limitations are not masked by the passing repository suite.

## Baseline preservation

The review plan and this evidence are version-controlled documentation, following
the existing `docs/images/` screenshot convention. The 71 PNGs, eight JSON files
and two Markdown documents total approximately 6.0 MiB (largest PNG: 316,206
bytes). No repository rule excludes this documentation evidence. Local links,
JSON parsing, filenames, PNG checksums and compressed image data were checked;
the PNGs contain no text metadata. Retained addresses are loopback or
documentation ranges, and the recorded accounts and infrastructure are fictional.
The unrelated private measurement files at the repository root are excluded.

Screenshots cover selected observations, not every JSON scenario: 22 baseline
and populated observations have text/DOM evidence only. All explicit Markdown
image links resolve. The original review's verification and completion statements
above describe that historical review; subsequent fixes are recorded separately
in the plan and maintained browser tests.
